# Engineering instructions

This is a **native Void SPA + API** starter on Cloudflare Workers. Follow Void's
conventions and the applicable BEP engineering skills. Read the official guides
bundled in `node_modules/void/docs/` before changing framework integration.

## Required workflow

1. Read relevant behavior in `spec/`; update it when behavior changes.
2. Use the native Void implementation. Remove replaced paths; do not add legacy
   compatibility layers or fallback branches for unpublished code.
3. Test behavior at the cheapest meaningful layer. Add `[spec: <id>]` evidence
   derived from the tags in `spec/*.feature`.
4. Run `pnpm verify`. Run `pnpm e2e` when a critical browser journey changes.

Do not weaken gates, exclude production logic from its owning proof layer, or
turn errors into defaults to make verification pass.

## Void conventions

- `void.config.ts`: app identity, Cloudflare target, static SPA routing and headers.
- `env.ts`: validated server environment schema; `.env` contains local values.
  Use `void secret put` for deployed server values. Never commit local secrets.
- `routes/api/*.ts`: file-based HTTP routes with named methods and `defineHandler`.
  Use `defineHandler.withValidator` for input. Do not create a manual Hono app,
  custom Worker entry point, or a parallel route registry.
- `middleware/*.ts`: ordered `defineMiddleware` modules for request/error logging,
  security headers, and authentication. All API routes require authentication
  except the explicit public config and health routes.
- `db/schema.ts`: SQLite schema through `void/schema-d1`. Use `void/db` and
  `@schema` for database queries; let Void infer and provision D1.
- `db/migrations/`: checked-in migrations generated by `void db generate`.
- `server/`: focused server helpers. Keep pure business rules independent of I/O;
  `server/notes.ts` owns note persistence. Do not recreate the retired
  use-case/port/repository/composition hierarchy for pass-through CRUD.
- `shared/`: authoritative runtime wire schemas and inferred DTOs.
- `.void/`: generated code and local state, never checked in. `void prepare`
  generates route, database and environment types after a fresh clone.

Expected application failures have stable error codes. Void owns schema-validation
responses. Unexpected failures reach the unified request boundary with their
stack and context; never disguise provider/network/programming failures as bad
credentials. Log request metadata without bodies. Derive mutation audit events
in middleware, with request and trace IDs.

## Browser application

**No SSR, SSG, or Void Pages.** `index.html` has an empty React mount point;
`src/main.tsx` mounts the SPA. Keep routing and rendering in the browser. Do not
add `pages/`, `main.ssr.*`, server loaders, or page actions.

- `src/app/`: providers, client router and shell.
- `src/routes/`: thin client page composition (distinct from root `routes/api/`).
- `src/features/<name>/`: capabilities with public `index.ts` exports.
- `src/shared/`: infrastructure and reusable UI primitives.

Use Void's generated typed `fetch` from `void/client` for app API calls. Decode
network and persisted payloads at runtime. Keep operation errors beside the
user's action and report unexpected browser failures centrally. Keep resource
creation/editing in dialogs, drawers, or secondary pages.

Authentication remains **OIDC Authorization Code + PKCE**. Keep the Access Token
in memory and send it as Bearer; never substitute the ID Token or persist tokens.
Do not add an application auth bypass for tests or silently change auth providers.

## Test ownership and gates

- Unit: pure business rules and deterministic logic; per-file coverage ≥90%,
  ≥95% for business rules.
- Component: Testing Library with MSW at the HTTP boundary; no internal-hook mocks.
- Integration: actual Void production build and preview in workerd, real D1,
  checked-in migrations, OIDC discovery/JWKS, JWT verification and serialization.
- E2E: critical browser journeys through the same production preview. Bootstrap
  in a unique temporary workspace with a separate `.env`, D1 state and dynamic
  application/OIDC ports. Never reuse developer configuration or state. Use zero
  retries, preserve failure evidence and clean runtime state on success/failure.

Keep accessibility/focus, CSP/injection, browser support, performance budgets and
reviewed visual baselines in the browser gate. `spec/*.feature` drives required
proof: traceability, integration behavior and critical E2E coverage remain 100%.

## Commands

- `pnpm verify`: lint, architecture, types, behavior inventory, tests, coverage, build.
- `pnpm test`: unit + component + isolated workerd integration tests.
- `pnpm test:fast`: unit + component tests.
- `pnpm test:integration`: build/migrate/preview in isolation and run HTTP integration tests.
- `pnpm test:coverage`: per-file unit/component coverage.
- `pnpm test:behavior`: behavior-layer and critical-path coverage.
- `pnpm e2e`: hermetic full-stack Playwright suite.
- `pnpm db:generate`: generate schema migrations.
- `pnpm db:migrate:local`: apply migrations to local Void state.

Use Node ≥24.21.0. Commits follow Conventional Commits. Delete obsolete code.
